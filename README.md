## これは何？

**Avatool** は、VRChat アバター改変をしている人向けの BOOTH アセット管理ツールです。

BOOTH での購入 → ダウンロード → zip 展開 → Unity インポート という、  
毎回繰り返す一連の作業を自動化し、複数プロジェクトへの安定した運用を実現します。

Windows ネイティブの Electron アプリとして動作し、Unity や VCC と直接連携します。  
初回セットアップを済ませれば、以降は最低限の操作で全工程が回せます。

## どんな問題を解決するか

### アセットが増えるほど管理が破綻する

BOOTH でアバター関連アセットを買い続けていると、こんな状況になりがちです。

- ダウンロードフォルダに zip が大量に溜まっていて、どれが最新か分からない
- 「この衣装、Unity に入れたっけ？」を毎回ライブラリと見比べている
- 新しいアバターを買って Unity プロジェクトを立ち上げるたびに、同じ VPM 導入手順を繰り返している
- PC 版と Quest 版で「どちらに何を入れたか」の管理が崩れてくる
- アセットのアップデートを見落として古いバージョンを使い続けている
- 複数アバターをかけ持ちしていると、どのアセットがどのアバター向けか追いきれない

### 手作業には限界がある

ひとつひとつは大した作業ではありません。  
でも 10 件、20 件と溜まると：

- zip を開いて unitypackage を探すだけで数分かかる
- 複数プロジェクトに同じ作業を繰り返すと疲弊する
- 「失敗したかもしれないインポート」を追いかけるログ管理が面倒になる
- 「あの衣装、どこに保存したっけ」という探索時間が増える

### Avatool が解決すること

| 手作業での状況 | Avatool での状況 |
|--------------|----------------|
| ダウンロードページを毎回ブラウザで開く | ライブラリ同期で一覧取得・管理 |
| zip を手動で展開して unitypackage を探す | ダウンロード後に自動展開・自動収集 |
| Unity に手動でドラッグ＆ドロップ | ボタン一発でインポートキューへ投入 |
| 複数プロジェクトに何度も同じ手順を繰り返す | プロジェクト別ルールで一括処理 |
| Unity を開かないとインポートできない | batchmode でバックグラウンド実行 |
| どれを入れたか自分で記録しておく | インポート履歴が自動で保存される |
| アップデートを見落とす | 更新ありアイテムのフィルタリングで即確認 |
| MA・NDMF・liltoon を毎回手動で入れる | VPM 導入を自動化できる |
| プロジェクト種別ごとに判断しながら作業する | ルールで分岐させて自動判断させる |

## 機能一覧

### ライブラリ管理

- BOOTH 購入アセットの一覧取得・ローカル同期
- 再同期時の差分判定（新規追加 / 更新あり / 変化なし を区別）
- アバター別フィルタリング（複数アバター持ちでも管理しやすい）
- 状態別フィルタリング（未ダウンロード / 未インポート / 更新あり）
- 作者名・アイテム名での検索・絞り込み
- アイテムの手動追加（BOOTH URL または商品 ID から登録）
- アバター対応情報のバッジ表示（対応アバター名が画像なしでも表示）
- サムネイル画像の表示とキャッシュ
- プレビューモーダルでの詳細表示・前後移動

### ダウンロード

- 複数アセットを選択してまとめてダウンロード
- バックグラウンドダウンロード（操作をブロックしない）
- zip / 7z / rar など各種アーカイブの自動展開
- パスワード付きアーカイブ（zip / 7z / rar）はパスワード入力プロンプトで対応
- unitypackage の自動収集（入れ子フォルダ構造にも対応）
- 1 アセット内に複数ファイルが含まれる場合もすべて収集
- 既存ファイルの有無に応じた再取得制御（不要な再ダウンロードを抑制）
- 失敗したアセットのみ再試行できる（リトライ対応）
- ダウンロード進捗のリアルタイム表示
- ダウンロード対象ファイルの個別選択（複数同梱でも選択可）

### Unity インポート

- Unity 起動中・未起動の両方に対応（自動判別）
- 複数アセットをキューに積んで順次処理
- 複数プロジェクトへの一括投入
- インポート進捗のリアルタイム通知
- インポート履歴の自動保存
- 同一プロジェクトへの重複実行ロック（多重起動を防止）
- 実行中フェーズの状態表示（準備 / 実行中 / 完了 / エラー）
- 失敗したパッケージだけ再実行できる構造
- 補助スクリプトの自動配置・自動クリーンアップ

### VCC / VPM 連携

- VCC のプロジェクト一覧を自動取得・Avatool 側へ同期
- VPM パッケージを `Packages/` 配下へ展開
- `manifest.json` の依存関係を自動反映
- 主な自動導入対象: Modular Avatar / NDMF / liltoon / SimpleFolderIcon（VPM）、FaceEmo（unitypackage）
- 各パッケージの導入有無を ON / OFF で制御可能
- 導入済みバージョンの追跡
- プロジェクトへの追加・削除に対応した再同期

### Auto Bootstrap（自動導入）

- プロジェクト検知で一連の処理を自動実行
- 処理内容: VPM 導入 → アセット選別 → unitypackage インポート → 結果記録
- プロジェクト名・パスのパターンによる導入ルール分岐
- 夜間・放置運用に対応

### スケジューラー

- 時間帯を指定して定時自動ダウンロードを実行
- 処理プロファイル（light / balanced / fast）で並行数を調整
- アプリ起動時に未取得アイテムを自動ダウンロード（Auto Bootstrap と連動）

### 設定・プロファイル管理

- 設定プロファイルの保存・読み込み（複数構成を使い分け可能）
- 設定・ライブラリ・ダウンロード済みファイルのエクスポート／インポート
- キーボードショートカットの完全カスタマイズ（23 種類）

### 操作ログ・通知

- すべての処理の操作ログを記録・閲覧
- ダウンロード・インポート完了時の通知
- エラー発生時の詳細メッセージ表示
- ヘルスチェック（異常検出時のみ通知、正常時は非表示）
- ログの全削除（確認ダイアログあり）
- 自動ダウンロード中の予期しないエラーのログ記録

## 動作環境

| 項目 | 要件 |
|------|------|
| OS | Windows 10 / 11（64-bit） |
| BOOTH アカウント | 必須（購入アセットへのアクセスに使用） |
| Unity Editor | 推奨。バックグラウンドインポートは Unity 未起動でも動作 |
| VCC（VRChat Creator Companion） | VCC 連携・VPM 導入機能を使う場合に必要 |
| ディスク空き容量 | ダウンロードするアセット量に依存 |
| インターネット接続 | BOOTH ライブラリ同期・ダウンロードに必要 |

> Unity Editor の場所は初期設定で手動指定します。  
> 複数バージョンを使い分けている場合は、プロジェクトごとに対応バージョンを設定することを推奨します。

## インストール

### 手順

1. [最新リリースページ](https://cdn.necco.xyz/file/avatool/latest.yml) からインストーラー（`.exe`）をダウンロードします
2. ダウンロードしたインストーラーを実行します
3. インストールウィザードに従ってセットアップします
4. アプリを起動すると BOOTH ログイン画面が表示されます。BOOTH アカウントでログインします

### アップデート

アプリ起動時に自動でアップデートを確認します。  
新しいバージョンがある場合は通知が表示され、アプリ内からそのまま更新を適用できます。  
手動でアップデートを確認したい場合は、設定画面から実行できます。

アップデート後も設定・履歴・ダウンロード済みファイルはそのまま引き継がれます。

### アンインストール

Windows の「アプリと機能」から Avatool を選択してアンインストールします。  
アンインストール時にデータ（`%APPDATA%\avatool\`）は削除されません。  
データも消したい場合は、アンインストール後にフォルダを手動で削除してください。

## 初期設定

初回起動後、以下の設定を行っておくと快適に使えます。

### 1. Unity Editor パスの設定

インポート機能を使うには、Unity Editor の実行ファイルパスを登録する必要があります。

1. 設定画面を開く
2. 「Unity Editor パス」に `Unity.exe` のフルパスを入力する

```
例:
C:\Program Files\Unity\Hub\Editor\2022.3.22f1\Editor\Unity.exe
```

複数のバージョンを使い分けている場合は、それぞれのバージョンのパスを登録できます。  
プロジェクトごとに使用する Unity バージョンを指定することも可能です。

### 2. VCC プロジェクトの同期

VCC 連携を使う場合は、VCC のプロジェクト一覧を取り込みます。

1. 設定画面の「VCC 連携」セクションを開く
2. 「プロジェクトを同期」を実行する
3. VCC 側で管理しているプロジェクトが Avatool に表示されます

### 3. BOOTH ライブラリの初回同期

インストール直後はライブラリが空なので、最初に同期を実行します。

1. メイン画面の「ライブラリ同期」ボタンを押す
2. BOOTH から購入一覧が取得されます（件数によって数分かかる場合があります）
3. 同期完了後、アセット一覧に購入アイテムが表示されます

### 4. Auto Bootstrap の設定（任意）

自動導入を使う場合は、Auto Bootstrap の設定を行います。

1. 設定画面の「Auto Bootstrap」セクションを開く
2. 導入するパッケージ（MA / NDMF / liltoon など）を選択する
3. プロジェクト別ルールを必要に応じて設定する
4. Auto Bootstrap を有効にする

## ライブラリ管理

### 同期の仕組み

BOOTH の購入ライブラリ情報を取得し、ローカルのメタ情報と統合します。  
再同期時は差分のみを更新するため、毎回全件取得する必要はありません。

差分の判定結果は以下の 3 種類で管理されます。

| 判定 | 意味 |
|------|------|
| 新規追加 | 前回の同期以降に購入したアイテム |
| 更新あり | 販売者がファイルを更新したアイテム |
| 変化なし | 前回と同じ状態のアイテム |

### フィルタリング

一覧の絞り込みは複数条件を組み合わせて使えます。

**状態フィルター**

| フィルター名 | 表示対象 |
|------------|---------|
| すべて | 全アイテム |
| 未ダウンロード | まだ一度もダウンロードしていないアイテム |
| 未インポート | ダウンロード済みだがインポートしていないアイテム |
| 更新あり | 販売者が更新したアイテム |

**アバターフィルター**

アイテムに設定されている対応アバター情報をもとに絞り込めます。  
「rurune だけ」「しお だけ」のように、特定アバター向けのアセットを素早く取り出せます。  
対応アバター画像が未登録のアイテムも、アバター名のバッジで識別できます。

**テキスト検索**

アイテム名・作者名でのインクリメンタル検索。ページ移動なしで即時絞り込みされます。

### アイテムの手動追加

BOOTH の URL または商品 ID を直接入力してアイテムを追加できます。  
ライブラリ同期で拾えない場合や、整理用に手動で登録したい場合に使います。

入力形式の例:

```
https://booth.pm/ja/items/1234567
1234567
```

入力形式が正しくない場合はエラーメッセージと入力例が表示されます。

### プレビューモーダル

アイテムをクリックすると詳細モーダルが開きます。

- アイテム名・作者名・サムネイル
- 対応アバター情報のパネル
- ダウンロード・インポートのアクションボタン
- 確認待ちアイテムの前後移動ボタン

## ダウンロード機能

### 選択とダウンロード開始

一覧からアイテムを選択してダウンロードを開始します。  
複数選択でまとめてダウンロードできます。

ダウンロード対象の選択モーダルでは、アイテム内のファイル一覧が確認できます。  
複数ファイルがある場合も、必要なものだけ選んでダウンロードできます。

### 展開と unitypackage 収集

ダウンロード後、以下の処理が自動で行われます。

1. アーカイブを展開（zip / 7z / rar など）
2. 展開結果を再帰的にスキャンして `.unitypackage` を収集
3. 1 アセット内に複数 package が含まれていてもすべて収集

> 例: 「衣装本体」「テクスチャ差分」「Quest 版」が 1 商品に同梱されていても、まとめて取り出せます。

### 再取得の制御

以下の状態に応じて再取得の挙動が変わります。

| 状態 | 挙動 |
|------|------|
| 未ダウンロード | 新規取得 |
| ダウンロード済み・変化なし | スキップ（再取得しない） |
| 更新あり | 最新ファイルで上書き取得 |
| 前回失敗 | 再試行 |

### ダウンロードの分割運用

「今はインポートしないが先にダウンロードだけ済ませる」という使い方ができます。

- 大量購入後にまずダウンロードだけ走らせておく
- インポートは週末や夜間にまとめてやる
- ストレージに余裕があれば、都合のいいタイミングでいつでもインポートできる

### 保存先

ダウンロードしたファイルは以下のパスに保存されます。

```
%APPDATA%\avatool\data\downloads\<itemId>_<name>\
```

## Unity インポート

### 2 つのインポートモード

Avatool は Unity の状態に応じて自動的に実行経路を切り替えます。  
どちらのモードを使うか、手動で選ぶ必要はありません。

#### 通常インポート（Live bridge モード）

Unity Editor が起動中のプロジェクトに対して使うモードです。

- Avatool から Unity に対してインポートキューを送信
- Unity が受け取り、エディタ上でインポートを実行
- 複数 package を順に処理
- 進捗をリアルタイムで返しながら実行
- Unity のエディタ状態をそのまま保てる

**向いている場面**:

- アバター改変中に衣装を追加したい
- 動作確認しながら順に試したい
- 少量のアセットをすぐ入れたい

**注意事項**:

Unity 側が 5 分以内に応答しない場合はタイムアウトし、操作ログに通知が表示されます。  
Unity が本当に起動中か、対象プロジェクトが開かれているかを確認してください。  
タイムアウトした場合はバックグラウンドモードに切り替えて再実行できます。

#### バックグラウンドインポート（batchmode モード）

Unity を起動せずにインポートを行うモードです。

- `Unity.exe -batchmode` で Unity を起動して処理
- アセットをまとめてバッチ実行
- 実行中はプロジェクトにロックをかけて多重起動を防止
- 完了後にロックを解除して Unity を終了
- 失敗時はエラー内容を返し、再実行しやすい形で終了

**向いている場面**:

- 夜間・放置で大量のアセットをまとめて処理したい
- 複数プロジェクトに同じアセットを一括投入したい
- Unity を開いたまま別作業をしたい（別プロジェクトに流す）
- Unity を起動する手間を省きたい

> **補足**: Unity が起動中であっても、対象プロジェクトが開かれていない場合はバックグラウンドモードが使われます。

### モードの比較

| 比較項目 | 通常インポート | バックグラウンドインポート |
|---------|-------------|----------------------|
| Unity 起動が必要か | 必要（対象プロジェクトを開いた状態） | 不要 |
| インポート中の Unity 操作 | 可（エディタは使い続けられる） | 不可（Unity が専有される） |
| 大量アセットの処理 | 向かない（時間がかかる） | 向いている |
| 複数プロジェクト同時処理 | 不可（1 プロジェクトずつ） | 可（順次実行） |
| 夜間放置運用 | 向かない | 向いている |

### インポート前チェック

Avatool はインポート実行前に以下を検証します。問題があれば投入前にエラーで止まります。

- `projectPath` が存在するか
- `packagePath` が存在するか
- ファイルが有効な `.unitypackage` か
- 同一プロジェクトで別のバックグラウンド処理が走っていないか

### 補助スクリプトの役割

インポートを安定して実行するため、必要に応じて補助 C# スクリプトを `Assets/Editor` に配置します。

| スクリプト | 役割 |
|-----------|------|
| `BoothBatchImporter.cs` | batchmode から呼び出してパッケージを一括インポートする |
| `BoothLiveImportBridge.cs` | Live bridge から受信したキューを順次インポートする |

設定の「Avatool スクリプト保持」を OFF にしている場合、処理完了後にこれらの `.cs` と `.meta` を自動でクリーンアップします。

```csharp
// BoothBatchImporter.cs（簡略版）
using UnityEditor;

public static class BoothBatchImporter
{
    public static void Import(string packagePath)
    {
        AssetDatabase.ImportPackage(packagePath, false);
    }
}
```

### 複数プロジェクトへの一括投入

同じアセットを複数プロジェクトに流す場合、プロジェクトをまとめて指定して一括実行できます。  
各プロジェクトへのインポートは順次実行され、それぞれ履歴に記録されます。

### インポート進捗の確認

実行中は画面上でフェーズを確認できます。

```
準備中 → インポート中 (3/10) → 完了
```

失敗した場合は：

- エラーの理由が操作ログに記録される
- 失敗したパッケージのみ再実行できる
- 成功分は再インポートしない

## VCC / VPM 連携

### VCC プロジェクトの取り込み

VCC（VRChat Creator Companion）の設定ファイルを読み取り、プロジェクト一覧を Avatool に取り込みます。  
VCC 側でプロジェクトを追加・削除した場合は、再同期することで反映されます。

VCC を経由して管理しているプロジェクトは、Avatool からそのまま操作できます。  
VCC 側への変更の書き戻しも行われます。

### VPM パッケージの導入

Avatool が対応する VPM パッケージを、指定プロジェクトの `Packages/` 配下に展開します。  
展開後は `manifest.json` の依存関係にも反映されます。

**自動導入に対応しているパッケージ（代表）**:

| パッケージ | 概要 | 導入制御 |
|-----------|------|---------|
| Modular Avatar | アバター改変の非破壊ワークフロー | ON / OFF |
| NDMF（Non-Destructive Modular Framework） | MA と連携する非破壊フレームワーク | ON / OFF |
| liltoon | VRChat 向け高品質シェーダー | ON / OFF |
| FaceEmo | 表情システム（unitypackage として導入） | ON / OFF |
| SimpleFolderIcon | プロジェクト内フォルダのアイコン設定 | ON / OFF |

各パッケージの導入有無は設定から個別に ON / OFF できます。  
導入済みバージョンも追跡されるため、「このプロジェクトには何が入っているか」を Avatool から確認できます。

### manifest.json の扱い

VPM パッケージを導入すると、`vpm-manifest.json` の `dependencies` に自動で追記されます。  
既に同じパッケージが入っている場合は、バージョン比較を行って必要な場合のみ更新します。  
手動で導入したパッケージがある場合も、上書きせず共存します。

## Auto Bootstrap（自動導入）

### 概要

Auto Bootstrap は「対象プロジェクトを検知したら、設定した手順を自動で実行する」機能です。  
手動でステップを踏まなくても、プロジェクトを作った後の初期セットアップをまるごと自動化できます。

### 実行される処理の順序

1. 対象プロジェクトの検知
2. VPM パッケージの導入（MA / NDMF / liltoon など、設定に従う）
3. 対象アセットの選別（プロジェクトルールに基づく）
4. `.unitypackage` のインポート（バックグラウンドモード）
5. 結果の記録・ログへの書き込み

### 設定できるオプション

| オプション | 内容 |
|-----------|------|
| MA / NDMF 導入 | Modular Avatar と NDMF を自動導入するか |
| liltoon 導入 | liltoon を自動導入するか |
| FaceEmo 追加 | FaceEmo を追加するか |
| SimpleFolderIcon 追加 | SimpleFolderIcon を追加するか |
| Avatool スクリプト保持 | 補助 `.cs` を処理後も残すか |

### プロジェクトルールとの組み合わせ

Auto Bootstrap 単体でも動作しますが、プロジェクト別ルールと組み合わせると、  
プロジェクトの種類ごとに導入内容を自動で切り替えられます。

例:

- `*_Quest*` に合致するプロジェクト → Quest 対応衣装のみを投入、liltoon は除外
- `*_PC*` に合致するプロジェクト → 全衣装 + liltoon + FaceEmo を投入
- `*_Test*` に合致するプロジェクト → VPM 導入のみ（アセット投入しない）

### 夜間・放置運用の例

```
仕事終わりに:
    1. Avatool でライブラリ同期（今日買ったアセットを取得）
    2. ダウンロード開始
    3. Auto Bootstrap を有効にしたまま PC を放置

翌朝:
    1. 操作ログを確認
    2. 失敗分だけ再実行
```

## プロジェクト別ルール設定

### 概要

プロジェクト名やフォルダパスのパターンに応じて「何を導入するか」を設定できます。  
同じアセットを持っていても、プロジェクトの用途によって導入内容を変えることができます。

### ルールの仕組み

ルールはパターンと条件のセットで定義します。

```
パターン: *_Quest*
  ├─ VPM: MA, NDMF のみ（liltoon は除外）
  ├─ アセット: Quest 対応タグが付いたものだけ
  └─ Auto Bootstrap: ON
```

```
パターン: *_PC*
  ├─ VPM: MA, NDMF, liltoon すべて
  ├─ アセット: すべて（フィルタなし）
  └─ Auto Bootstrap: ON
```

```
パターン: *_Test*
  ├─ VPM: MA, NDMF のみ（最小セット）
  ├─ アセット: 投入しない
  └─ Auto Bootstrap: ON（VPM 導入のみ実行）
```

### 推奨する命名規則

ルール適用を安定させるために、プロジェクト名に用途を含める命名規則をおすすめします。

| プロジェクト名の例 | 適用するルール |
|-----------------|-------------|
| `Avatar_PC_Main` | PC 版フルセット |
| `Avatar_Quest_Main` | Quest 版軽量セット |
| `Avatar_Test_Dev` | 最小セット（開発・検証専用） |
| `Avatar_PC_Sub` | PC 版（サブアバター用） |
| `rurune_PC_Main` | アバター名を先頭に含める例 |

### 実務上の効果

- 「この衣装は Quest 対応だっけ？」かどうかを考えずにルールで分岐できる
- 新しいプロジェクトを作るたびに同じ手順を繰り返さなくていい
- 複数アバターを管理していても、ルールを揃えれば混乱しにくい

## インポート履歴・メタ管理

### 保存される情報

Avatool はすべての処理ごとに履歴を記録します。

- いつ・どのアセットを・どのプロジェクトへインポートしたか
- インポートの成否とエラー内容
- ダウンロードしたファイルのバージョン・ファイルパス
- パッケージに関連するメタ情報（アバター対応情報など）

### 活用できるシーン

- 「先月どの衣装を入れたか」を逆引きできる
- 再インストール後に「どのプロジェクトに何が入っていたか」を確認できる
- 失敗ログを見て「どのタイミングでどんなエラーが出たか」を切り分けられる
- 更新判定のベースとして使われる（同一バージョンなら再インポートしない）
- どのアセットが「まだ一度もインポートされていないか」を把握できる

### データの保存場所

```
%APPDATA%\avatool\data\
  ├─ meta\          # アイテムのメタ情報（JSON）
  ├─ downloads\     # ダウンロードしたファイル
  │    └─ <itemId>_<name>\
  └─ history\       # インポート履歴（JSON）
```

## 処理フロー（全体）

Avatool の処理は大きく 5 ステップで構成されます。

```
[1] BOOTH ライブラリ同期
         │
         │  購入アイテムの一覧を取得し、
         │  ローカルのメタ情報と統合する
         │  (差分のみ更新)
         │
         ▼
[2] 対象アセットの選択・ダウンロード
         │
         │  一覧から対象を選び、
         │  バックグラウンドでダウンロードする
         │  (失敗分のみリトライ可能)
         │
         ▼
[3] 展開と unitypackage 収集
         │
         │  アーカイブを展開し、
         │  .unitypackage を再帰的に収集する
         │  (複数 package 同梱にも対応)
         │
         ▼
[4] Unity プロジェクトへ投入
         │
         │  ┌─ Unity 起動中 ──▶ Live bridge（通常インポート）
         │  └─ Unity 未起動 ──▶ batchmode（バックグラウンドインポート）
         │
         │  ※ 複数プロジェクトへは順次実行
         │  ※ 同一プロジェクトへの重複実行はロックで防止
         │
         ▼
[5] 履歴・メタ情報の保存
         │
         │  結果を記録し、次回処理に活用する
         │  (更新判定・失敗切り分けに使用)
         ▼
       完了
```

手動実行と Auto Bootstrap の両方で、同じフローが回ります。

## ユースケース別ガイド

Avatool の使い方は、ユーザーの状況によって異なります。  
自分に近いケースを参考に、最初の設定を進めてみてください。

---

### ケース A: アバター 1 体・プロジェクト 1 つのシンプル運用

**状況**: 1 体のアバターだけ改変している。PC 版のみ。アセットは月 5〜10 件ペース。

**おすすめ設定**:

- Auto Bootstrap: ON（MA / NDMF / liltoon を自動導入）
- プロジェクト別ルール: 設定不要（ルールなしで全アセットを投入）
- ダウンロード: 都度手動（溜めても OK）

**典型的な使い方**:

1. BOOTH で購入したら Avatool でライブラリ同期
2. 未ダウンロードのアイテムを選択してダウンロード
3. Unity を開いた状態でインポートボタンを押す
4. 完了後に Unity で確認

シンプルな構成なので、難しい設定は不要です。

---

### ケース B: PC 版・Quest 版を並行管理している

**状況**: 同じアバターで PC 版と Quest 版のプロジェクトを別々に持っている。

**おすすめ設定**:

- プロジェクト名: `<アバター名>_PC_Main` / `<アバター名>_Quest_Main`
- プロジェクト別ルール:
  - `*_PC*` → liltoon あり・全アセット
  - `*_Quest*` → liltoon なし・Quest 対応アセットのみ
- Auto Bootstrap: ON

**典型的な使い方**:

1. 新しい衣装を購入してダウンロード
2. 「Quest 対応」タグがついている衣装だけ Quest 版にも投入するよう選択
3. バックグラウンドインポートで PC 版・Quest 版にまとめて流す
4. 翌朝ログ確認

Quest 対応かどうかの判断を手動でしなくていいのが最大のメリットです。

---

### ケース C: 複数アバターをかけ持ちしている

**状況**: アバターを 3〜4 体持っていて、それぞれに衣装・小物を管理している。

**おすすめ設定**:

- アバターフィルターを活用（作業するアバターで絞り込んでから操作）
- プロジェクト命名規則を徹底（アバター名を先頭に含める）
- 例: `rurune_PC_Main` / `shio_PC_Main` / `nix_PC_Main`

**典型的な使い方**:

1. 今日は「rurune」の衣装を追加したい
2. アバターフィルターで `rurune` を選択
3. 未インポートのアイテムが絞り込まれる
4. `rurune_PC_Main` を指定してインポート
5. 次は `shio` に切り替えて同様に操作

アバターフィルターを先に絞ってから作業すると、誤ったアセットを別アバターに入れるミスを防げます。

---

### ケース D: 大量のアセットを一気に整理したい

**状況**: 今まで手動管理していたが、溜まりすぎて管理しきれなくなった。Avatool を入れて一気に整理したい。

**おすすめ手順**:

1. Avatool をインストールして初回ライブラリ同期を実行
2. 全アイテムが一覧に表示されるので、まず状態を確認
3. 「未ダウンロード」フィルターで取得できていないアイテムを確認
4. まとめてダウンロード（時間がかかるので夜間に走らせる）
5. ダウンロード完了後、バックグラウンドインポートで全プロジェクトに流す
6. 履歴を見ながら「どれが入ってどれが入っていないか」を整理

> 数百件あっても、ダウンロードとインポートは自動でまとめて処理できます。ひとつひとつ手作業でやる必要はありません。

---

### ケース E: Auto Bootstrap でほぼ全自動にしたい

**状況**: なるべく操作を減らして、買ったら勝手に入っていてほしい。

**おすすめ設定**:

- Auto Bootstrap: ON（全オプション有効）
- プロジェクト別ルール: 使用プロジェクト分をすべて設定
- 自動ダウンロード: 有効（Auto Bootstrap を ON にすると起動時に未取得アイテムを自動ダウンロード）

**典型的な使い方**:

1. BOOTH でアセットを購入
2. Avatool がバックグラウンドで定期同期・自動ダウンロード
3. プロジェクトを Unity で開くと Auto Bootstrap が検知してインポートを実行
4. 気がついたら入っている

> ここまで自動化するには、ライブラリの自動同期と自動ダウンロードを有効にする必要があります。設定から確認してください。

## 運用例

### 週次アセット管理

週に 1 回まとめて処理する運用例です。

```
月〜金: アセットを BOOTH で購入（Avatool はまだ使わない）
    │
土曜の朝:
    ├─ ライブラリ同期（今週の購入分を取得）
    ├─ 「未ダウンロード」フィルターで対象を確認
    └─ まとめてダウンロード開始

土曜の夜（寝る前）:
    └─ バックグラウンドインポートを流しておく

日曜の朝:
    └─ 操作ログを確認して失敗分だけ再実行
```

この運用だと、週に 2 回 Avatool を触るだけで管理が回ります。

### 複数プロジェクト・複数アバター管理

PC 版と Quest 版を並行して運用している場合の例です。

```
プロジェクト構成:
  rurune_PC_Main      ← PC 版メイン（liltoon + 全衣装）
  rurune_Quest_Main   ← Quest 版（MA/NDMF + Quest 対応衣装のみ）
  shio_PC_Main        ← 別アバター PC 版
  shio_Quest_Main     ← 別アバター Quest 版
  test_Dev            ← 検証用（最小セット）
```

プロジェクト別ルールを設定しておくと、  
新しい衣装を買ったとき「PC 版には入れて Quest 版には入れない」を自動で判断してくれます。

### 大量購入後の一括処理

セールや新作ラッシュで 20〜30 件まとめて買った場合の例です。

1. ライブラリ同期で全件取得
2. 「未ダウンロード」フィルターで対象を絞る
3. 全選択してダウンロード開始
4. ダウンロード完了後、バックグラウンドインポートを PC 版・Quest 版に流す
5. 翌朝ログを確認して失敗分のみ再実行

> 通信エラーや配布側の一時不調で一部失敗しても、失敗分だけ再取得できるので全部やり直しにはなりません。

### 新規プロジェクト立ち上げ

新しいアバターを買って Unity プロジェクトを立ち上げるときの例です。

1. VCC で新規プロジェクトを作成
2. Avatool で VCC プロジェクトを再同期
3. 新しいプロジェクトが一覧に表示される
4. Auto Bootstrap が検知して VPM 導入 → アセットインポートを自動実行
5. 完了後にログを確認してアバター改変作業に入れる

Auto Bootstrap があれば、手順 2 以降は自動で完了します。

### アセット更新の適用

お気に入りの衣装が更新された場合の例です。

1. ライブラリ同期を実行
2. 「更新あり」フィルターで更新されたアイテムを確認
3. 対象を選択して再ダウンロード（最新ファイルで上書き）
4. 再インポートしたいプロジェクトを選んでインポート実行

## トラブルシューティング

### BOOTH 関連

**ライブラリが取得できない**

BOOTH Cookie が期限切れになっている可能性があります。

1. Avatool から BOOTH ログイン画面を開く
2. BOOTH アカウントで再ログインする
3. ライブラリ同期を再実行する

> ブラウザの BOOTH ログイン状態は Avatool の認証に影響しません。Avatool 側で独立してログインが必要です。

**アイテムが一覧に表示されない**

- ライブラリ同期を実行してください
- 購入直後は BOOTH 側の反映に時間がかかる場合があります。数分待ってから再同期してください
- 手動追加機能を使って BOOTH URL または商品 ID から直接登録することもできます

**同期に時間がかかる**

購入件数が多い場合、初回同期は数分かかることがあります。完了まで待ってください。  
2 回目以降は差分のみを更新するため、大幅に速くなります。

### ダウンロード関連

**ダウンロードが途中で止まる**

- ネットワーク接続を確認してください
- 一時的な通信障害の場合は、失敗したアセットを選択して再試行してください
- BOOTH の配布サーバー側の問題の場合は時間を置いてから再試行してください

**unitypackage が見つからないと言われる**

- 展開後のフォルダを確認し、手動で `.unitypackage` の場所を確認してください
- パスワード付き zip など、自動展開できない形式の場合は手動で展開してください
- アイテムの購入形態によっては `.unitypackage` でなく別形式の場合があります

**ダウンロード先のファイルが見当たらない**

保存先は `%APPDATA%\avatool\data\downloads\` です。  
エクスプローラーのアドレスバーに `%APPDATA%\avatool\data\downloads\` と入力して開けます。

### Unity インポート関連

**インポートが始まらない**

1. 設定画面の Unity Editor パスが正しいか確認してください
2. 指定したパスの `Unity.exe` が実際に存在するか確認してください
3. Unity のバージョンとプロジェクトの対応バージョンが合っているか確認してください
4. 管理者権限が必要な場合は、Avatool を管理者として実行してみてください

**Live インポートが 5 分でタイムアウトする**

- 対象プロジェクトが Unity Editor で開かれているか確認してください
- Unity がコンパイル中など別処理で応答できない状態の場合は、完了後に再試行してください
- バックグラウンドインポートに切り替えることで回避できます

**バックグラウンドインポートが完了しない・スタックする**

- 対象プロジェクトが Unity で開かれていると多重起動ロックが発生します。Unity を閉じてから実行してください
- 同一プロジェクトで別の Avatool バックグラウンド処理が走っていないか確認してください
- Unity のライセンス認証が切れている場合、batchmode が起動直後に終了する場合があります
- 操作ログにエラー内容が記録されているので確認してください

**補助スクリプトが残ったままになる**

- 設定の「Avatool スクリプト保持」を OFF にしてください
- 手動で削除する場合:
  ```
  Assets/Editor/BoothBatchImporter.cs
  Assets/Editor/BoothBatchImporter.cs.meta
  Assets/Editor/BoothLiveImportBridge.cs
  Assets/Editor/BoothLiveImportBridge.cs.meta
  ```
  上記ファイルを Unity プロジェクト内から削除してください

**「このプロジェクトは既に処理中です」と表示される**

- 前回のバックグラウンドインポートが正常に終了しなかった場合、ロックが残ることがあります
- 操作ログで前回の実行状況を確認してください
- 問題がなければ、ロックを手動解除してから再実行してください

### Auto Bootstrap 関連

**Auto Bootstrap が実行されない**

- 設定画面で Auto Bootstrap が有効になっているか確認してください
- VCC プロジェクトの同期が完了しているか確認してください
- プロジェクト別ルールのパターンが正しく設定されているか確認してください
- 既存プロジェクトに対しては、「再実行を許可する」設定が必要な場合があります

**Auto Bootstrap が途中で止まる**

- 操作ログでどのフェーズで止まったか確認してください
- VPM 導入フェーズで止まっている場合は VCC 連携の設定を確認してください
- インポートフェーズで止まっている場合は Unity の起動状態やパスを確認してください
- 対象アセットが 0 件の場合は「ルールに合致するアセットがない」ために処理が完了扱いになっています

**特定プロジェクトだけ Auto Bootstrap が実行されない**

- プロジェクト名がルールのパターンに合致しているか確認してください
- パターンは大文字・小文字を区別します。`*_PC*` は `myavatar_pc_main` には合致しません
- 既にインポート済みとして記録されている場合は再実行がスキップされます

### ログ・通知関連

**「ヘルスチェック: エラー N 件 / 警告 N 件」が表示される**

起動時のヘルスチェックで問題が検出されました。操作ログで詳細を確認してください。

よくある原因:
- 参照しているプロジェクトパスが存在しない（プロジェクトを移動・削除した）
- ダウンロード済みとして記録されているファイルが存在しない（手動で削除した）
- メタ情報に不整合がある

多くの場合、実害はなく処理を続行できます。気になる場合は該当エントリを整理してください。

**操作ログが大量になりすぎる**

「ログを全削除」ボタンで一括削除できます。確認ダイアログが表示されるので意図しない削除を防げます。  
削除後のログは復元できません。

### VCC 連携関連

**プロジェクトが同期されない**

- VCC が正しくインストールされているか確認してください
- VCC の設定ファイルの場所が標準パスと異なる場合は、設定画面で手動指定してください
- VCC でプロジェクトを追加した直後は、Avatool 側で再同期が必要です

**VPM パッケージが導入されない**

- VCC が有効なリポジトリに接続できているか確認してください
- 対象パッケージが設定で有効になっているか確認してください
- 導入済みの場合は再導入がスキップされます。バージョンを確認してください

## よくある質問（FAQ）

**Q. Unity が起動しているかどうかで手動で切り替える必要がありますか？**

A. 不要です。Avatool が自動で判断します。Unity が起動中なら Live bridge、未起動ならバックグラウンドで実行します。対象プロジェクトが開かれているかどうかも自動で確認します。

---

**Q. 同じアセットを複数回インポートしてしまいますか？**

A. 履歴とバージョン情報を参照し、同一バージョンのアセットを同一プロジェクトに再インポートすることはありません。更新がある場合のみ再インポートが実行されます。

---

**Q. BOOTH でアセットが更新された場合、通知は来ますか？**

A. ライブラリ同期時に更新差分を検出します。「更新あり」フィルターで対象を確認して手動でダウンロード・インポートするか、Auto Bootstrap を使って自動化できます。リアルタイム通知には非対応です。

---

**Q. PC を変えたときにデータは移行できますか？**

A. `%APPDATA%\avatool\data\` をコピーすることで、メタ情報とインポート履歴を移行できます。ただし、BOOTH の認証情報（Cookie）はデバイス固有のキーで暗号化されているため、移行後に再ログインが必要です。

---

**Q. Quest 版と PC 版で同じアセットを別々に管理できますか？**

A. はい。プロジェクト別ルールでパターンを設定することで、同じアセットでも投入先・投入条件をプロジェクトごとに分けられます。

---

**Q. VPM パッケージを手動で導入した場合、Avatool と競合しますか？**

A. 基本的に競合しません。`manifest.json` を確認して既に導入済みの場合は再導入をスキップします。ただし、Avatool が管理するバージョンと手動導入バージョンが異なる場合の挙動は、パッケージの仕様に依存します。

---

**Q. アプリのデータはどこに保存されますか？**

A. すべてのデータは `%APPDATA%\avatool\` 配下に保存されます。アンインストール時にデータは削除されません。手動で削除する場合は、アンインストール後にこのフォルダを削除してください。

---

**Q. バックグラウンドインポート中に PC をシャットダウンしてしまいました。データは壊れますか？**

A. インポート途中で中断された場合、プロジェクトのロックが残ることがあります。  
次回起動時に操作ログを確認し、必要に応じて対象プロジェクトのロックを手動解除してから再実行してください。Unity プロジェクト自体は、インポート途中で止まった場合でも通常は壊れません。

---

**Q. 複数の BOOTH アカウントを使い分けできますか？**

A. 現在は 1 アカウントのみ対応しています。複数アカウントの切り替え機能は対応していません。

---

**Q. ダウンロードしたファイルを手動で整理しても問題ありませんか？**

A. Avatool はファイルパスを履歴に保存しています。ファイルを手動で移動・削除すると、  
次回インポート時に「ファイルが見つからない」エラーが発生する場合があります。  
ダウンロードしたファイルは Avatool の管理フォルダ内に置いておくことを推奨します。

---

**Q. 1 商品に複数の unitypackage が入っている場合、どれがインポートされますか？**

A. ダウンロード時の選択モーダルで、どのファイルをインポート対象にするか選べます。  
すべて選択することも、一部だけ選ぶこともできます。

---

**Q. BOOTH 以外のアセットも管理できますか？**

A. 手動追加機能を使えば、BOOTH URL がないアセットも登録できます。  
ただし、ダウンロードや更新チェックは BOOTH 経由のものに限られます。  
手動追加アイテムはファイルパスを直接指定してインポートのみ利用できます。

---

**Q. Auto Bootstrap はいつ実行されますか？**

A. VCC プロジェクトの同期後、新規プロジェクトが検知されたときに実行されます。  
既存プロジェクトへの自動実行は、設定で「再実行を許可する」を有効にした場合のみ行われます。

---

**Q. インポート履歴はどれくらい保持されますか？**

A. 現在は件数・期間の上限なく保持されます。ストレージに問題が生じる場合は手動で整理してください。

---

**Q. アイテムのサムネイルが表示されません。**

A. BOOTH から画像を取得できていない場合、サムネイルが空欄になります。  
ライブラリ同期を再実行するか、プレビューモーダルを開くと再取得が試みられます。  
BOOTH 側の CDN に一時的な問題がある場合は時間を置いてください。

---

**Q. 自動更新チェックを無効にできますか？**

A. 設定画面の「自動アップデート」を OFF にすることで無効化できます。  
ただし、セキュリティや安定性のため、定期的に手動でアップデートを確認することを推奨します。

---

**Q. アセットを誤って手動追加してしまいました。削除できますか？**

A. 手動追加したアイテムはライブラリ一覧から削除できます。  
対象のアイテムをプレビューモーダルで開き、削除オプションから実行してください。

---

**Q. プロジェクトを VCC から削除した場合、Avatool 側にも反映されますか？**

A. VCC プロジェクトを再同期することで反映されます。  
同期前は Avatool 側に削除済みプロジェクトが残った状態になりますが、実害はありません。

---

**Q. ダウンロード中にアプリを閉じてしまいました。続きから再開できますか？**

A. ダウンロードが中断された場合、次回起動時に未完了のアイテムが「ダウンロード失敗」として表示されます。  
該当アイテムを選択して再ダウンロードしてください。部分的にダウンロードされたファイルは自動で再取得されます。

---

**Q. バックグラウンドインポートと通常インポートを手動で選べますか？**

A. 基本的には自動判別ですが、設定から「常にバックグラウンドモードを使う」を選択することで強制的にバックグラウンドモードにできます。

## 運用のヒント

### プロジェクト命名規則を最初に決める

ルール適用の安定性は命名規則の質に依存します。最初に決めておくと後から楽になります。

```
推奨パターン:
<アバター名>_<用途>_<識別子>

例:
rurune_PC_Main      ← PC版メイン
rurune_Quest_Main   ← Quest版メイン
shio_PC_Main        ← 別アバターPC版
test_Dev            ← 検証・開発用
```

### 最初は小さく試す

Auto Bootstrap やプロジェクト別ルールは、最初に 1〜2 件の小さい対象で動作確認してから範囲を広げるのがおすすめです。  
大量に流して全部失敗するより、1 件試して確認する方が早く解決できます。

### バックグラウンド運用時は Unity バージョンを固定する

batchmode は指定された `Unity.exe` を呼び出すため、Unity バージョンをプロジェクトごとに管理している場合は注意が必要です。  
プロジェクトが想定するバージョンと Avatool に設定した Unity パスが合っているか確認してください。

### 「先に DL だけ」の運用を使う

大量購入した直後にすぐインポートする必要がない場合は、まずダウンロードだけ完了させておき、  
インポートは週末・夜間など都合のいいタイミングでまとめて流すことができます。  
ダウンロード済みであれば、何度でも同じファイルからインポートできます。

### VPM 導入対象をプロジェクト間で揃える

同じアバター・同じ用途のプロジェクトが複数ある場合、VPM 導入対象を統一しておくとトラブルが減ります。  
「このプロジェクトだけ liltoon が入っていない」という事態を避けられます。

### 操作ログを定期的に確認する

自動処理を多用する場合は、操作ログを週 1 回程度確認する習慣をつけると問題の早期発見につながります。  
エラーは詳細メッセージ付きで記録されるため、ログから原因を特定しやすくなっています。

### アバターフィルターを活用する

複数アバターを持っている場合は、作業前にアバターフィルターで絞ってから作業すると、  
「関係ないアセットも混じって管理が複雑になる」を防げます。

### 確認ダイアログに慣れる

Avatool では重要な操作に確認ダイアログが表示されます。

- 操作ログの全削除
- Unity プロジェクトのリストからの削除

素早く使いたい場合でも、確認を飛ばさずに進める習慣をつけておくと誤操作を防げます。

### 更新チェックを習慣化する

Avatool は起動時に自動でアップデートを確認しますが、BOOTH 側のアセット更新は同期しないと分かりません。  
週に 1 回ライブラリ同期を回すだけで「更新あり」フィルターから最新状態を把握できます。

### バックグラウンドインポートの活用タイミング

バックグラウンドインポートは以下のタイミングで特に効果的です。

- **就寝前**: 寝ている間に大量アセットを処理させる
- **外出前**: 外出中に処理を完了させておく
- **別の Unity 作業中**: 別プロジェクトが Unity で開かれているときに、他プロジェクトへ流す

起動中の Unity プロジェクトとは別のプロジェクトをターゲットにすれば、作業中断なしで並行処理できます。

### 「先に DL・後でインポート」の分割運用

ダウンロードとインポートは別々のタイミングで行えます。

```
【DL フェーズ】 PCがオンのとき
  → まとめてダウンロード（バックグラウンドで走らせておく）

【インポートフェーズ】 都合のよいとき
  → ダウンロード済みファイルからインポート実行
  → 何度でも同じファイルから実行できる
```

ネットワークの負荷を分散させたいときや、「DL だけ今日やっておいてインポートは後で確認しながら」という使い方に向いています。

## 上級者向け設定

基本的な使い方に慣れてきたら、以下の設定でより細かい制御ができます。

### インポート対象のカスタマイズ

デフォルトでは、ダウンロードしたアーカイブ内のすべての `.unitypackage` がインポート対象になります。  
ダウンロード選択モーダルで個別に選択することで、特定のファイルだけを対象にできます。

よくある用途:
- 「本体」と「差分パッチ」が同梱されているとき、本体のみを先にインポートする
- Quest 版と PC 版が同梱されているとき、今は PC 版だけインポートする
- テクスチャだけ差し替えたいとき、テクスチャ用 package だけ選ぶ

### 特定プロジェクトへのアセット固定

アイテムごとに「いつもこのプロジェクトに入れる」という紐付けを設定できます。  
設定しておくと、インポート時のプロジェクト選択を省略できます。

### ダウンロードフォルダのカスタマイズ

デフォルトの保存先（`%APPDATA%\avatool\data\downloads\`）を変更したい場合は、  
設定画面の「ダウンロード先フォルダ」を変更してください。

外付け HDD や大容量ドライブを指定すると、ストレージを節約できます。

> 変更後は既存ファイルが移動されません。過去のダウンロードは旧パスに残ります。  
> 必要であれば手動でファイルをコピーしてください。

### 自動ダウンロードの設定

Auto Bootstrap を有効にすると、アプリ起動時に未取得アイテムを自動でダウンロードします。  
これは独立した設定ではなく、Auto Bootstrap の起動時処理として動作します。

**注意事項**:
- 大量に未取得アイテムがある状態で有効にすると、起動時にまとめて自動ダウンロードが始まります
- 最初は少数のアイテムで動作確認してから本格運用することを推奨します

### ヘルスチェックのカスタマイズ

起動時のヘルスチェックは、内部データの整合性を検証します。  
チェック結果に問題がない場合は通知を表示しません（正常時は無通知）。

チェックで検出される主な問題:
- 参照先ファイルが存在しないメタエントリ
- プロジェクトパスが無効になったエントリ
- インポート履歴の不整合

これらが検出された場合は操作ログに詳細が表示されます。

## インポート動作の詳細仕様

### Live bridge の仕組み

通常インポート（Live bridge モード）は、Avatool と Unity Editor がローカルで通信する仕組みです。

```
Avatool
  │
  │  インポートキューをファイル経由で送信
  │
  ▼
BoothLiveImportBridge.cs（Unity 内）
  │
  │  キューを受信して AssetDatabase.ImportPackage() を呼び出す
  │
  ▼
Unity Editor（インポート実行）
  │
  │  完了 / エラーを Avatool に返す
  ▼
Avatool（結果を受信・ログ記録）
```

このため、Unity が起動していない場合やプロジェクトが開かれていない場合は、ブリッジが存在せずタイムアウトになります。

### batchmode の仕組み

バックグラウンドインポートでは、Unity を `-batchmode` フラグで起動します。

```
Avatool
  │
  │  BoothBatchImporter.cs をプロジェクトに配置
  │
  ▼
Unity.exe -batchmode -executeMethod BoothBatchImporter.Import ...
  │
  │  引数で渡された .unitypackage を順にインポート
  │
  ▼
Unity（終了）
  │
  ▼
Avatool（終了コードと結果ファイルを確認・ログ記録）
```

Unity の起動・終了までをまるごとバックグラウンドで処理するため、  
PC の前を離れている間でも安全に実行できます。

### インポート後のクリーンアップ

設定の「Avatool スクリプト保持」が OFF の場合、インポート完了後に以下を削除します。

```
Assets/Editor/BoothBatchImporter.cs
Assets/Editor/BoothBatchImporter.cs.meta
Assets/Editor/BoothLiveImportBridge.cs
Assets/Editor/BoothLiveImportBridge.cs.meta
```

ON にしている場合、これらのスクリプトはプロジェクトに残り続けます。  
残しておいても動作に支障はありませんが、不要であれば手動で削除できます。

### エラー時の挙動

| エラー種別 | 挙動 |
|-----------|------|
| 対象ファイルが存在しない | そのファイルをスキップして次を処理 |
| Unity 起動失敗 | エラーログを記録して処理中断 |
| タイムアウト | ログに通知して残りをキャンセル |
| 多重実行ロック | 既存処理の完了を待つよう通知 |
| インポート一部失敗 | 成功分を記録し、失敗分を再実行可能な状態で終了 |

## 技術仕様・補足

### 認証と Cookie

Avatool の BOOTH 認証は Cookie を使用します。

- Cookie は Electron の `safeStorage` API（App-Bound Encryption）でデバイス固有のキーを使って暗号化
- 同一デバイス・同一バイナリからのみ復号可能
- Cookie は `%APPDATA%\avatool\` 配下に暗号化して保存
- ブラウザの BOOTH ログイン状態とは独立しています

### 補助スクリプトの仕様

インポート実行時に `Assets/Editor/` に配置される C# スクリプトについて。

- 配置先: `Assets/Editor/`
- 自動クリーンアップ: 設定の「Avatool スクリプト保持」が OFF の場合、処理完了後に `.cs` と `.meta` を削除
- 手動削除: `Assets/Editor/BoothBatchImporter.cs` / `BoothLiveImportBridge.cs` とそれぞれの `.meta` を削除

### データフォーマット

インポート履歴・メタ情報は JSON 形式でローカルに保存されます。  
Avatool を通じてのみ参照・更新することを想定しており、手動編集はサポートしません。

### 自動アップデートの仕組み

- アプリ起動時に CDN からバージョン情報を確認
- 新しいバージョンがあればインストーラーをバックグラウンドでダウンロード
- 準備完了後に通知を表示し、ユーザーが任意のタイミングで適用できる
- アップデート後も設定・履歴・ダウンロード済みファイルは引き継がれる

### ヘルスチェック

起動時に内部状態の整合性チェックを実施します。

- エラー・警告がゼロの場合は通知を表示しない（正常時は無通知）
- 問題が検出された場合のみ「error N / warn N」形式で通知
- ヘルスチェックの詳細は操作ログから確認できます

## PC 移行・再インストール時のガイド

### PC を買い替える・OS を再インストールする場合

Avatool のデータは `%APPDATA%\avatool\` に保存されています。  
以下の手順でデータを移行できます。

**移行できるもの**:

- アイテムのメタ情報（どんなアイテムを持っているか）
- インポート履歴（どのプロジェクトに何を入れたか）
- ダウンロード済みファイル（`downloads\` フォルダ）

**移行できないもの**:

- BOOTH の認証情報（Cookie）→ 移行後に再ログインが必要
- 設定値（Unity パスなど）→ 移行後に再設定が必要

**移行手順**:

1. 旧 PC の `%APPDATA%\avatool\` を USB や OneDrive などにコピー
2. 新 PC に Avatool をインストール
3. `%APPDATA%\avatool\` に旧 PC のデータをコピー
4. Avatool を起動して BOOTH に再ログイン
5. 設定画面で Unity Editor パスを再設定

### Avatool を再インストールする場合

アンインストールしてから再インストールしても、`%APPDATA%\avatool\` は削除されません。  
再インストール後もデータはそのまま引き継がれます。

### ダウンロードしたファイルの再取得が必要な場合

`%APPDATA%\avatool\data\downloads\` 配下にダウンロード済みファイルが存在しない場合、  
Avatool は「未ダウンロード」として扱い、再取得を要求します。  
ファイルを別の場所に移した場合は、元のパスに戻すか再ダウンロードしてください。

## 既知の制限

### プラットフォーム

- **Windows 専用**: macOS / Linux には対応していません。VRChat アバター改変は Windows 環境が主流なため、Windows のみをサポートしています

### 認証・セキュリティ

- **Cookie の移行不可**: BOOTH 認証 Cookie はデバイス固有のキー（Electron safeStorage）で暗号化されています。バックアップや別端末への移行はできません。PC を変えた場合や OS を再インストールした場合は再ログインが必要です
- **複数 BOOTH アカウント非対応**: 1 つの BOOTH アカウントのみ管理できます。アカウントの切り替えは現時点で対応していません

### Unity 連携

- **Unity バイナリ依存**: batchmode は設定した `Unity.exe` のパスを直接呼び出します。Unity Hub でバージョンを管理している場合、バージョンアップ後は Avatool 側の設定更新が必要です
- **同一プロジェクトの並列インポート不可**: 同じプロジェクトへの同時インポートはロックで防止されています。並列処理はできません
- **Unity ライセンス必要**: batchmode 実行には Unity の有効なライセンス認証が必要です。ライセンス切れの場合、batchmode が正常に動作しません

### ダウンロード・展開

- **パスワード付きアーカイブ**: 展開時にパスワード入力プロンプトが表示されます。zip / 7z / rar に対応しています
- **一部アーカイブ形式の非対応**: 特殊なアーカイブ形式（一部の古い `.rar` など）は展開できない場合があります

### アセット管理

- **BOOTH 以外のアセット**: BOOTH 購入品以外のアセットは、手動追加機能でのみ登録できます。自動ダウンロードや更新チェックには対応していません
- **リアルタイム更新通知なし**: BOOTH 側でアセットが更新されても、Avatool 側のライブラリ同期を実行するまで検出されません
- **削除済みアイテムの追跡**: BOOTH から購入アイテムが削除（販売終了など）された場合、Avatool 側での自動削除は行われません

### パフォーマンス

- **大量件数での初回同期**: 購入アイテムが数百件以上ある場合、初回のライブラリ同期に数分かかることがあります
- **大量バックグラウンドインポート**: 多数のアセットを一度にバックグラウンドインポートする場合、Unity の起動・終了を繰り返すため時間がかかります

## よくある操作チートシート

操作を素早く参照したいときのまとめです。

### BOOTH 関連

| やりたいこと | 操作 |
|------------|------|
| 新しく買ったアセットを取り込む | ライブラリ同期を実行 |
| 特定アバター向けアセットだけ表示する | アバターフィルターパネルでアバターを選択 |
| 更新されたアセットを探す | 「更新あり」フィルターを選択 |
| まだダウンロードしていないものを確認する | 「未ダウンロード」フィルターを選択 |
| まだ Unity に入れていないものを確認する | 「未インポート」フィルターを選択 |
| BOOTH にないアセットを手動登録する | アイテム一覧末尾の追加タイルから登録 |
| 認証が切れた | 設定または通知から BOOTH に再ログイン |

### ダウンロード関連

| やりたいこと | 操作 |
|------------|------|
| 複数アセットをまとめてダウンロードする | 一覧で複数選択 → ダウンロードボタン |
| ダウンロード済みファイルの場所を確認する | `%APPDATA%\avatool\data\downloads\` を開く |
| ダウンロードに失敗したアイテムを再試行する | 失敗アイテムを選択して再ダウンロード |
| 特定のファイルだけ取得する | ダウンロード選択モーダルでファイルを個別選択 |

### Unity インポート関連

| やりたいこと | 操作 |
|------------|------|
| Unity が開いているプロジェクトにすぐ入れる | 通常インポートを実行（自動で Live bridge が使われる） |
| Unity を閉じたまま夜間に流す | バックグラウンドインポートを実行 |
| 複数プロジェクトに同じアセットを入れる | インポートダイアログでプロジェクトを複数選択 |
| インポート失敗したアセットだけ再実行する | 操作ログで失敗を確認 → 対象のみ再インポート |
| 残った補助スクリプトを削除する | 設定の「Avatool スクリプト保持」を OFF → 次回インポート後に自動削除 |

### VCC / VPM 関連

| やりたいこと | 操作 |
|------------|------|
| VCC のプロジェクト一覧を更新する | 設定 → VCC 連携 → プロジェクトを同期 |
| 新しいプロジェクトに MA/NDMF を自動導入する | Auto Bootstrap の MA/NDMF 導入を ON に設定 |
| liltoon だけ自動導入から外す | Auto Bootstrap 設定で liltoon 導入を OFF |

### トラブル時

| 状況 | まず確認すること |
|------|---------------|
| 何も動かない | 操作ログにエラーが出ていないか確認 |
| BOOTH に接続できない | 再ログイン → 再同期 |
| インポートが始まらない | 設定の Unity パスが正しいか確認 |
| タイムアウトが出る | Unity が起動中か・対象プロジェクトが開かれているか確認 |
| バックグラウンドが終わらない | 同じプロジェクトが Unity で開かれていないか確認 |
| ヘルスチェックエラーが出る | 操作ログの詳細を確認（多くの場合は実害なし） |
